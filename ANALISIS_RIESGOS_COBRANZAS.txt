## 3️⃣ BÚSQUEDA AUTOCOMPLETE - ANÁLISIS DETALLADO

### CONECTIVIDAD ACTUAL

Cobranza Múltiple usa:
```typescript
<select>
  {estudiantes.map(est => <option>)}
</select>
```

Conectado a:
- setEstudianteSeleccionado(id)
- setConceptosPendientes([...])
- Carga de conceptos via obtenerConceptosPendientes()

### CAMBIOS A REALIZAR

```typescript
// ANTES: Simple select
// DESPUÉS: Input + filtering + autocomplete

// Nueva lógica:
const [busquedaEstudiante, setBusquedaEstudiante] = useState('')
const [mostrarDropdown, setMostrarDropdown] = useState(false)

// Filtrar estudiantes en tiempo real
const estudiantesFiltrados = useMemo(() => {
  if (!busquedaEstudiante) return []
  return estudiantes.filter(e =>
    `${e.nombre} ${e.apellido}`.toLowerCase().includes(busquedaEstudiante)
  )
}, [busquedaEstudiante, estudiantes])

// Render
<input
  value={busquedaEstudiante}
  onChange={(e) => setBusquedaEstudiante(e.target.value)}
/>
{mostrarDropdown && (
  <ul>
    {estudiantesFiltrados.map(e => (
      <li onClick={() => {
        setEstudianteSeleccionado(e.id)
        setBusquedaEstudiante(`${e.nombre} ${e.apellido}`)
        setMostrarDropdown(false)
      }}>
        {e.nombre} {e.apellido}
      </li>
    ))}
  </ul>
)}
```

### 🚨 RIESGOS CRÍTICOS

**RIESGO 1: State desincronizado (ALTO)**
```
¿Qué pasa si el usuario escribe pero no selecciona?
- busquedaEstudiante ≠ estudiante.nombre
- Click en "Registrar cobro" usa estudianteSeleccionado (null)
- Modal de confirmación rompe

SOLUCIÓN:
- Require selección de dropdown (no permitir input libre)
- Al hacer click, setEstudianteSeleccionado() ANTES de cargar conceptos
```

**RIESGO 2: Hook order de useEffect (MEDIO)**
```
Actual:
useEffect(() => {
  if (estudianteSeleccionado && conceptos.length > 0) {
    obtenerConceptosPendientes(...)
  }
}, [conceptos, estudianteSeleccionado, ...])

¿Qué pasa si agrego estado de búsqueda?
- Podría trigger múltiples renders
- Conceptos podrían cargarse 2 veces
- Performance degrada

SOLUCIÓN:
- Separar lógica de búsqueda en useEffect diferente
- No incluir busquedaEstudiante en dependencies del otro
```

**RIESGO 3: Dropdown event handling (MEDIO)**
```
¿Qué pasa si:
- Usuario abre dropdown
- Usuario hace click afuera
- Dropdown se cierra pero valor persiste
- Usuario hace click en otro lugar

SOLUCIÓN:
- useEffect para detectar clicks fuera
- O usar useRef para detectar blur
- Ambas soluciones agregan complejidad
```

### ❌ IMPACTO EN COMPONENTES

```
SI FALLO en autocomplete:
- Estudiante no se selecciona → Modal se abre con estudiante = null
- ModalConfirmacionCobro recibe undefined → CRASH

SI FALLO en actualizar conceptos:
- conceptosPendientes no carga → Usuario ve vacío
- Usuario no puede cobrar

SI FALLO en estado sincronizado:
- Cobro se registra a estudiante equivocado
- PROBLEMA CRÍTICO EN BD
```

### 🛡️ MITIGACIÓN

Para hacer esto SEGURO:
1. Crear componente separado SearchableSelect
2. Agregar validación antes de permitir registro
3. Tests unitarios de autocomplete
4. Verificar que estudianteSeleccionado !== null antes de registrar
